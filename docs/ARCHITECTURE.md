# Архитектура Broma 16 Assistant

## Слои

```
┌──────────────────────────────────────────────────────────────┐
│ Renderer (React + TypeScript)                                 │
│ чат · панель действий · FAQ · обращения · релизы · почта      │
└───────────────▲──────────────────────────────────────────────┘
                │ contextBridge (window.api), IPC invoke + события
┌───────────────┴──────────────────────────────────────────────┐
│ Main process (Electron, Node 24)                              │
│                                                               │
│  AgentOrchestrator ──► ToolExecutionLayer (tools.ts)          │
│        │                     │                                │
│        │                     ├── KnowledgeBase (Freshdesk)    │
│        │                     ├── EmailService (IMAP/SMTP)     │
│        │                     ├── BrowserAutomation (Chromium) │
│        │                     ├── FileService (PDF/DOCX/XLSX)  │
│        │                     └── SQLite (node:sqlite)         │
│        │                                                      │
│  ProviderManager ──► OpenAI · Anthropic · Gemini · compatible │
│  SecretStore ─────► safeStorage (Keychain/DPAPI/libsecret)    │
│  Scheduler ───────► почта · follow-up · обновление FAQ        │
└──────────────────────────────────────────────────────────────┘
```

## Поток запроса

1. Пользователь пишет сообщение → `chat:send` → сообщение в SQLite.
2. `AgentOrchestrator.run()` собирает историю (последние 40 сообщений, лимит по символам),
   системный промпт с профилем, статусом FAQ, контактами и шаблонами.
3. Запрос к провайдеру со стримингом; текст сразу уходит в UI (`event:delta`).
4. Если модель вернула tool_calls:
   - `safe`-инструменты выполняются сразу, результат пишется как `tool`-сообщение;
   - `confirm`-инструменты создают `pending_actions` и карточку подтверждения, цикл останавливается;
   - после подтверждения действие выполняется, placeholder результата обновляется, цикл продолжается.
5. Финальный ответ сохраняется вместе с источниками, панель действий показывает шаги.

## Ключевые решения

| Решение | Причина |
|---|---|
| `node:sqlite` вместо нативного better-sqlite3 | нет компиляции при установке, работает на Windows/macOS «из коробки» |
| Свой SSE-парсер и адаптеры провайдеров | единый интерфейс, смена модели не трогает агента; поддержка reasoning-моделей и vision |
| Chromium внутри Electron для кабинета | не нужен отдельный Playwright-браузер (~300 МБ), сессия изолирована партицией `persist:broma16` |
| Декларативные инструменты с `risk` | политика подтверждений в одном месте, легко добавить новый инструмент |
| BM25 по 43 статьям | быстро, офлайн, без внешних embedding-сервисов; цитаты и ссылки обязательны |
| SQLite как единственное хранилище | история, tool-calls, письма, тикеты и настройки переживают перезапуск |

## Миграции

Схема создаётся идемпотентно (`CREATE TABLE IF NOT EXISTS`), недостающие колонки добавляются
в `Db.migrate()` через `ALTER TABLE`. Версионирование пока не требуется.

## Расширение

Новый инструмент: объект в `electron/agent/tools.ts` (`name`, `description`, `parameters`, `risk`, `run`).
Новый провайдер: адаптер, реализующий `LlmAdapter`, + запись в `presets.ts`.
Новая интеграция (например, Google Sheets): отдельный сервис в `electron/`, инструмент-обёртка,
проброс через `ToolContext`.
